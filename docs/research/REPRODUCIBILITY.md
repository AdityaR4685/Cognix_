# COGNIX Framework — Reproducibility Guide

Research is invalid if it cannot be reproduced. COGNIX mandates the following standards for all published results.

## 1. Global Seeding
All experiments must call `cognix.utils.seeding.set_random_seed(seed, torch_deterministic=True)` at initialization. This fixes seeds for:
- Python `random`
- NumPy `np.random`
- PyTorch `torch.manual_seed`
- PyTorch CUDA backends

## 2. Run Artifacts
Executing an experiment script must automatically generate a `results/<run_id>` folder containing:
- `config.yaml`: The exact configuration used.
- `metadata.json`: Includes Git commit hash, Python version, library versions.
- `metrics.json`: The final numerical results.

## 3. No Hardcoded Benchmarks
Benchmark results (e.g., "37% communication reduction") must never be hardcoded into READMEs, documentation, or the Dashboard. They must be generated by scripts reading `metrics.json`. Claims in the README should distinguish between **Targets/Hypotheses** and **Measured Results**.

## 4. Pipeline Determinism
The `DecisionEngine` uses `_safe_call` to handle agent failures. If an agent fails non-deterministically (e.g., network timeout), the pipeline handles it gracefully, but it breaks exact numerical reproducibility. 
- For formal evaluation: Use offline datasets where agent outputs are pre-computed or executed deterministically.
- For live simulation: Report aggregated statistics (e.g., mean/std over 5 runs) rather than single-run numbers.
