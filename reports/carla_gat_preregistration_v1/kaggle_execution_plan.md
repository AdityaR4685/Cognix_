# Kaggle execution plan (design only)

This file specifies a future authorized run. No notebook, trainer, graph dataset, upload or training is executed in this milestone. Use one T4, one process, no distributed training.

## Inputs and present readiness gate

The N=20 compact handoff supplies clean FIT features/agent outputs and CAL pseudo rows. It does **not** contain FIT pseudo examples. Camera/Seg corruptions require the preserved raw TRAIN frames; the compact features cannot reconstruct those pixel recipes. Therefore first implement the separately authorized local FIT-only pseudo export using the frozen protocol and original extractors. Export compact features/scores/probabilities/UQ plus provenance; keep raw images outside Kaggle. Do not synthesize corruptions directly in embedding space. CAL pseudo rows are rejected by the graph data loader.

## Ordered workflow

1. Verify SHA256SUMS, protocol/schema hashes, N=20 source/cache/handoff hashes, canonical node order and validity masks. Require GNSS probability/UQ to remain null. Pin/log Python, NumPy, PyTorch, CUDA and dependency lock versions from the future validated environment; no runtime dependency upgrades.
2. Generate FIT pseudo **locally** after explicit authorization, or load the matching compact FIT-only export. Reuse every clean compact parent row. Apply only the frozen five recipes with base seed 0 and production per-tick seed t. Check hash/provenance, causal windows, non-effect guard, exact untouched nodes and per-node labels. A no-effect parent loses both members of the pair. Do not load any CAL pseudo as graph training data. Publish one canonical row-keyed dataset and skip ledger before model initialization.
3. Verify split_manifest.json exactly; never resplit in the notebook. Group clean/pseudo by parent scenario. Accept only the 12 GRAPH_TRAIN and 3 GRAPH_VALIDATION scenarios. Assert CAL intersection is empty. Materialize float32 [B,3,3] node tensors, immutable adjacency and raw-E prior inputs from float64 canonical agent outputs. No fitted normalization and no recalibration.
4. Implement the preregistered future report/adapter-side trainer. Compose the unchanged generic GAT layers with a batched wrapper; the current generic .fit is a per-observation loop and is not the frozen mini-batch trainer. Verify vectorized equivalence to unmodified layers, receiver/sender direction, no self-loops, same parameter count, neutral-prior identity and monotonic sender suppression on synthetic fixtures. Do not edit generic production or frozen synthetic code. Implement the separate NoGraph shared MLP; do not substitute the frozen identity NoGraph plugin.
5. For seeds 101,202,303,404,505, train NoGraph, then StandardGAT, then EpistemicGAT with the same data and explicit epoch permutations. Reset Python/NumPy/Torch/CUDA RNGs for every run. Standard/Epistemic initial parameter tensors are cloned identically per seed; match initial dropout RNG state. Each uses the same maximum budget/early-stop rule. No hyperparameter search.
6. Use float32, Adam(lr=0.001, weight_decay=0.0001), batches of 256, maximum 100 epochs, dropout 0.1, no AMP, scheduler, gradient clipping or multi-GPU. Set CUBLAS_WORKSPACE_CONFIG=:4096:8 before CUDA initialization; disable TF32 and cuDNN benchmarking; enable deterministic algorithms. DataLoader workers=0. If a nondeterministic operation is rejected, stop and record it; no silent fallback. Construct each epoch's identical graph-row permutation using PCG64(seed+epoch_index), independent of the Torch dropout RNG.
7. Evaluate only GRAPH_VALIDATION, with dropout disabled. Monitor equal-scenario BCE. The patience tracker updates only when loss improves by more than 1e-5; otherwise increment its counter, stopping after 10 such epochs. Independently save the lowest-loss checkpoint among executed epochs, earliest epoch on exact ties. Use no CAL/TEST outcome for early stopping, scaling, sampling, architecture or threshold selection.
8. Save per-run checkpoints (including optimizer/RNG states), run config and environment, epoch histories, best epoch, failure status and protocol/data/source hashes. Save row-keyed predictions for GRAPH_TRAIN and GRAPH_VALIDATION: scenario, tick, pair/row keys, recipe, role, true target, q_normal, p_corruption and method/seed/checkpoint hash. Persist per-layer evaluation attention for the same frozen validation rows; do not choose visually favorable rows after seeing performance.
9. Select the corruption threshold exclusively from graph validation as metrics_spec.json defines. Save every seed's per-scenario and pooled metrics, per-recipe diagnostic counts, all paired differences and the predefined small-sample statistical summaries. No best-seed model or sample selection. These are development results, since validation also selects checkpoints/thresholds and upstream one-class agents used all FIT scenarios.
10. After all primary outputs are frozen, run the single exploratory GNSS-raw auxiliary-input condition with the same samples/splits/seeds and explicit secondary architecture. Keep it separate from primary tables. Do not introduce GNSS-only pseudo or a GNSS calibrated probability/UQ. Save all failures and negative results.
